# 库存扣减的一致性要求（RULES）

本文是验收依据。代码与本文不符即为缺陷。

## 1. 不超卖

- 任意并发场景下，`stock.qty` 不得为负。
- 并发 N 个请求抢购同一 SKU 时，成功数不得超过初始库存。

## 2. 原子性

- 一次扣减要么「库存减少 + 订单写入」都成功，要么都不生效。
- 库存不足时，**不得**留下任何订单记录。
- 读当前库存与写回新库存必须在同一个事务内完成，不得基于读到的旧值直接写回。

## 3. 幂等

- `order_id` 是幂等键：同一个 `order_id` 重复调用，只允许扣减一次。
- 重复调用应返回第一次的结果，而不是再次扣减或报错。

## 4. 并发冲突

- 遇到 `database is locked` 这类可重试的冲突，必须退避后重试（最多 5 次），不得直接抛给调用方。
- 重试期间不得重复扣减。

## 5. 失败回滚

- 扣减过程中任何一步失败，已写入的部分必须回滚。

## 6. 验收方式

- 初始库存 10，20 个并发请求各买 1 件：成功数必须为 10，最终库存为 0，订单表恰好 10 行。
- 同一 `order_id` 连续调用 2 次：库存只减一次，两次返回值一致。
- 库存不足的请求：抛异常，且订单表不新增记录。
